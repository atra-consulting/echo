# CLAUDE.md

This file provides guidance to coding agents when working with code in this repository.

## Project Overview

Zeugnisgenerator (formerly echo) is an Angular 21 web application that assembles German employment reference letters (Arbeitszeugnisse) from pre-written text modules. It supports final references (Abschlusszeugnis) and interim references (Zwischenzeugnis) with gender-specific text variants. Built by atra.consulting and published as open source.

The tool gives no legal advice. The README and the UI carry a "keine Rechtsberatung" disclaimer; never claim, in any language, that the tool or its output is legally safe, compliant or verified.

## Commands

- **Install**: `npm ci`
- **Dev server**: `ng dev` or `npm run dev` (serves at localhost:4200, auto-reloads on changes). The UI needs the backend: run `npm run build:server && npm run start:server` (127.0.0.1:8081) in a second terminal; `proxy.conf.json` forwards `/api` and `/mcp` to it.
- **Build**: `ng build` (outputs to `dist/zeugnisgenerator/browser`). The initial bundle exceeds the 1 MB budget and triggers a warning (known and accepted); do not raise the budgets.
- **Run tests**: `ng test` (Karma + Jasmine, watch mode in Chrome); single run: `ng test --watch=false --browsers=ChromeHeadless`
- **Run single test**: `ng test --watch=false --browsers=ChromeHeadless --include='src/app/path-to-component/**/*.spec.ts'` (quote the glob, zsh aborts on an unquoted one)
- **Static serve**: `npm start` (uses `serve` on port 8080; static files only, without the backend the UI loads no text modules)
- **Backend**: `npm run build:server` (type check with `server/tsconfig.json`, esbuild bundle to `dist/server/main.cjs`, plus `dist/server/node_modules` with the external `@google-cloud/firestore` and its dependencies from the lockfile), `npm run test:server` (node:test specs in `server/**/*.spec.ts`, bundled to `dist/server-test`; the Firestore contract test runs only with `FIRESTORE_EMULATOR_HOST` set), `npm run start:server` (127.0.0.1:8081; drafts and MCP off by default)
- **Production-like local run**: `docker compose up --build` (web/nginx on 127.0.0.1:8080, backend in the same network namespace, Firestore emulator, dev user and a marked dev key; `MCP_AUTH=none docker compose up --build` enables `/mcp` for the dev user; the backend listens on all interfaces like on Cloud Run and the healthcheck calls `/api/health` with the container IP as Host)
- **CI**: `.github/workflows/ci.yml` runs `npm ci`, the build and the tests of app and backend on Node 22 (npm 10), builds both images and smoke-tests them with compose and curl, for every pull request and push to main, also in forks. `deploy.yml` reuses it as test gate (`workflow_call`).
- **Dependencies**: change them only with npm 10 (e.g. `npx -y npm@10 install <pkg>`). The Docker build uses npm 10, and `package-lock.json` (lockfileVersion 2) must stay installable with it; npm 11 drops nested entries that npm 10 needs. Otherwise install with `npm ci`; even a plain `npm install` with npm 11 rewrites the lockfile.

## Architecture

### Standalone Components (no NgModules)

All components use standalone architecture with OnPush change detection.

**Route flow**: `/certificate-chooser` → `/user-input`. The preview (ReferenceOutputComponent) is embedded in the user-input page. `app.routes.ts` also defines `/reference-output`, but the UI never navigates there.

- **CertificateChooserComponent**: Landing page, selects certificate type, shows the user's drafts (DraftListComponent) and the disclaimer footer
- **DraftListComponent**: The stored drafts (status, last edit) with open, JSON export (not encrypted) and delete, plus JSON import and the retention note; hidden when the backend answers `/api/drafts` with 404 (no draft store)
- **UserInputComponent**: Main form container with Material stepper, orchestrates sub-components (IntroComponent, PositionComponent, BlockSelectorComponent, BlockRatingComponent, ReferenceOutputComponent); explicit save of the draft, "final" and JSON export in the top bar (final drafts are read-only and can only be saved as a new draft)
- **ReferenceOutputComponent**: Live preview of the generated reference letter text with edit and copy; the disclaimer hint sits outside the "paper" so it is never copied or exported. Edits in edit mode only change `DataStorageService.flowText` in memory and are overwritten by the next `updateFlowText()`.

### Services

- **reference-text.ts**: Framework-free assembly of the reference text (placeholders, order of topics and subtopics, choice of the female text modules) and the translation between the app's `SelectedBlocks` (text per topic/subtopic) and the API's selections by number (`blocksToSelections`, `selectionsToBlocks`). Shared by the app and the backend; must not import Angular or browser APIs.
- **DataStorageService** (`data-storage.service.ts`): Central state management. Loads the text modules from the backend (`GET api/certificate-types/{type}/text-modules`), manages form data and selected text blocks, converts them into a `ReferenceDraft` for saving, and delegates placeholder replacement and text assembly to `reference-text.ts`. The live preview is assembled locally (instant, inputs reach the backend only on save). localStorage stays as buffer for unsaved work (inputs, selections, certificate type and the id/status of the open draft). On a salutation change the selected sentences move to the same positions in the other variant.
- **DraftsService** (`drafts.service.ts`): REST calls for `/api/drafts` (list, create, replace, finalize, export/download, import, delete); `available` is false when the backend has no draft store.
- **GoogleAuthService** (`google-auth.service.ts`): Google OAuth2 sign-in/sign-out via Google Identity Services (GIS) token client. Loads the GIS script on demand, exposes `getAccessToken()` for API calls.
- **GoogleDocService** (`google-doc.service.ts`): Exports to Google Docs (copies the template via Drive API, inserts text into the copy) and Google Sheets (creates spreadsheet, appends form data + selections). Plain fetch against the Google REST APIs, no client library.

### Backend (`server/`)

Node backend shared by the UI and AI agents: REST API under `/api` (OpenAPI at `/api/openapi.json`) and an MCP server under `/mcp` (MCP TypeScript SDK, Streamable HTTP, stateless: new server and transport per request). Bundled with esbuild into `dist/server/main.cjs`; `server/Dockerfile` builds its image from the repository root. Ports & adapters, no DI framework (plain constructor injection):

- **core/** (framework-free: no Express, MCP SDK or Google Cloud imports): `ports.ts` (TextModuleSource, DraftStore with plain domain drafts `StoredDraft`, IdentityProvider, Clock, Identity, DraftConflictError; nothing about encryption), `text-modules.ts` (catalog with numbered sentences, translation of selections into `SelectedBlocks` collecting all problems; farewell and future_wishes expose their rating levels directly), `steps.ts` (guided workflow "Box für Box": steps in template order with a `selection_rule` derived from the structure, one step box, progress with `open_steps`/`next_step`/`complete`, draft text with the current wording per step), `drafts.ts` (DraftService use cases on a DraftStore: create, get, replace, update one step, delete, finalize, export, import, expiry), `schemas.ts` (zod schemas shared by REST and MCP, versioned `ReferenceDraft`, export format).
- **adapters/**: `bundled-text-modules.ts` (JSON from `src/assets/`), `file-text-modules.ts` (`TEXT_MODULES_DIR`, for forks), `memory-draft-store.ts` (plain drafts in process memory, for tests and forks without persistence), `firestore-draft-store.ts` (collection `drafts`; encrypts the payload itself as a persistence concern: `toDocument`/`fromDocument` map the domain draft to a document with keyId, fresh IV and ciphertext, AAD = id + owner + schemaVersion; drafts that do not decrypt are left out of the list; the list query needs the composite index owner asc + updatedAt desc, created by `deploy.yml`; the emulator ignores indexes), `aes-gcm-cipher.ts` (the adapters' `DraftCipher` interface and the AES-256-GCM key ring, JSON `{"active","keys"}`, given to the Firestore store by `main.ts`), `iap-identity.ts` (verified `x-goog-iap-jwt-assertion`; never trust the plain `x-goog-authenticated-user-*` headers; FixedIdentityProvider for local dev). Every adapter of a port passes the contract tests in `adapters/*.spec.ts`.
- **http/** (driving adapter): `app.ts` (Express app; `/api/health` is answered before the DNS-rebinding Host check so probes with any Host work; identity middleware, `/api/drafts`, `/api`, `/mcp`, error handler that never logs bodies), `api.ts` (stateless endpoints: certificate types, steps, step, `POST /api/references`, text modules for the UI), `drafts-api.ts` (`/api/drafts…`), `openapi.ts`, `google-oauth.ts` (OAuth proxy to Google for `MCP_AUTH=google`: verified accounts of `GOOGLE_ALLOWED_DOMAIN`, encrypted JWTs with `TOKEN_SECRET`, registration limited to claude.ai callbacks and loopback URIs).
- **mcp/mcp-server.ts** (driving adapter): draft tools `list_drafts`, `create_draft`, `get_step`, `update_draft`, `get_draft`, `finalize_draft`, `export_draft`, `import_draft`, prompt `zeugnis_erstellen`, instructions describing the workflow. Tool descriptions and results carry the "keine Rechtsberatung" disclaimer.
- **main.ts**: composition root and the only place that reads `process.env` (`API_PORT`, `HOST`, `PUBLIC_URL`, `TRUST_PROXY`, `TEXT_MODULES_DIR`, `IAP_AUDIENCE`, `DEV_USER_EMAIL`, `DRAFT_STORE`, `DRAFT_ENCRYPTION_KEY`, `RETENTION_DAYS`, `MCP_AUTH`, `GOOGLE_*`, `TOKEN_SECRET`). Fails closed: Firestore without a valid key ring, drafts without a verified identity, `DEV_USER_EMAIL` next to `IAP_AUDIENCE` or on Cloud Run (`K_SERVICE`), `MCP_AUTH=none` on a non-loopback host without IAP (or, locally, `DEV_USER_EMAIL`) all refuse to start. `TRUST_PROXY` is 2 on Cloud Run (front end + nginx).

Rules: drafts belong to the email of the verified identity; foreign, missing and expired drafts are all 404; final drafts are read-only (409); every stored draft has a `revision` and `DraftStore.save` takes the expected revision (optimistic lock; Firestore in a transaction), so a write that lost a race (e.g. update vs. finalize) fails with `DraftConflictError` (409 `draft_conflict`) instead of overwriting; every write sets `expireAt = updatedAt + RETENTION_DAYS`, reads don't; the export has no owner or internal id and the import always creates a new `draft`. Encryption is a concern of the persistence adapter, not of the core. Never log request bodies, draft contents or key material. Keep atra-specific values (project, service name, IAP audience, secret names, registry) in env, `deploy.yml` or the manifest, never in code; no links to internal repositories or issues in code or public docs.

### Configuration

- `src/app/google.config.ts`: OAuth client id (public by design; the consent screen only admits atra.consulting accounts) and the id of atra.consulting's Google Docs template. Forks set their own values.

### Data Templates

Four JSON files in `src/assets/` (`data_abschlusszeugnis.json`, `data_zwischenzeugnis.json` and their `data_female_*` variants, which `IntroComponent` requests when the salutation "Frau" is selected). The backend bundles them and serves them via the API; `angular.json` excludes `data_*.json` from the web build, so they are not public static files. Both variants must have the same structure, because selections by number apply to either. They define structured text blocks organized by topic (intro, position, performance, behavior_evaluation, conclusion, farewell, future_wishes). Only the intro and position topics list sentences directly; every other topic must contain subtopics (`user-input.component.html` renders nothing else), some with rating levels (sehr gut, noch gut, etc.). Placeholder tokens are replaced with form values at runtime; only names matching `{\w+}` are placeholders, so `{department/company_part}` in the shipped modules stays in the text verbatim. The text modules are not MIT-licensed; do not change their content as part of code changes. Backend tests derive their selections from the catalog so they stay independent of the wording.

## Deployment

- **Docker**: two images, both multi-stage on Node 22-alpine (npm 10). `Dockerfile` (web and ingress): `nginxinc/nginx-unprivileged:stable-alpine` serving the Angular build (plus `3rdpartylicenses.txt`) on `$PORT` (default 8080) and reverse-proxying `/api/`, `/mcp` and the MCP OAuth paths to the backend on `127.0.0.1:${API_PORT}` (config in `deploy/nginx/`). `server/Dockerfile` (backend): bundle plus `node_modules` for Firestore, listens on `127.0.0.1:8081` by default. The ingress is the UI container itself; a separate proxy container is not needed.
- **atra.consulting's instance**: one Cloud Run service with two containers (`web` is the only ingress, `api` a sidecar reached via localhost). `.github/workflows/deploy.yml` on push to main: tests (`ci.yml`), keyless auth via Workload Identity Federation, builds and pushes `echo` (web) and `echo-api` (backend), creates the Firestore composite index (idempotent), fills `deploy/cloud-run/service.yaml` (image tags, revision name, the platform's runtime service account from the repository secret `RUNTIME_SA`, the IAP audience from the service's project number) and applies it with `gcloud run services replace`, then checks that the revision became ready. The manifest restates the platform's service settings (`run.googleapis.com/ingress: all`, `run.googleapis.com/iap-enabled: "true"`); `services replace` replaces the whole service, so never drop them. Backend env in the manifest: `HOST=0.0.0.0`, `IAP_AUDIENCE`, `MCP_AUTH=none`, `TRUST_PROXY=2`, `DRAFT_STORE=firestore`, `RETENTION_DAYS=90`, `DRAFT_ENCRYPTION_KEY` from Secret Manager (`draft-encryption-key`, key `latest`). The backend's startup probe is TCP (no Host header involved). Startup CPU boost on, no min instances (scale to zero). The infrastructure is managed outside this repository by atra.consulting's internal GCP platform, which also maintains the required repository secrets. `deploy.yml` also enables the Firestore TTL policy on `drafts.expireAt` (skipped when active or being created). Drafts count as deleted from `expireAt` on; Firestore deletes them afterwards, usually within a day; docs and UI say "nicht mehr abrufbar und danach gelöscht".
- **Name**: The infrastructure and the Cloud Run service keep the old name `echo` (`SERVICE_NAME: echo` in `deploy.yml`, `metadata.name` in the manifest), independent of the repository and app name. Never rename the repository without the matching change on the GCP side.
- **Forks**: `deploy.yml` and `build-and-release.yml` (semantic-release) only run in the `atra-consulting` organization (`github.repository_owner` guard).
- **MCP**: on behind IAP in atra.consulting's instance (`MCP_AUTH=none` with `IAP_AUDIENCE`): `/mcp` requires the verified IAP assertion like `/api`, the owner of the drafts is its email. Local agents such as Claude Code pass IAP with the user's ID token (`Proxy-Authorization: Bearer`, generated by `scripts/mcp-iap-headers.mjs` as `headersHelper`; the OAuth client must be allowlisted for IAP programmatic access, tokens expire after an hour). Only claude.ai connectors (calling from Anthropic's servers) cannot pass IAP; they would need `MCP_AUTH=google` on a public service, which is not available for echo (`oeffentlich` is refused for migrated projects, only the service named after `github_repo` may be public, and public projects must not hold personal data without IT/DSB approval). Do not make the service public without that clearance.
